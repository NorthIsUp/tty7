# agents come back after a reboot

`Fork-Feature: agent-resume`. The commit that carries this feature is `fork(agent-resume): …` on `main-niu`.

## Fork-owned files

| file | what it holds |
|---|---|
| `src/ui/agent_resume.rs` | Continue All Agents (every sleeping agent tab), `--continue` and the launch/restart wakes (all queued on `wake_pool`; `LaunchWake`, taken once by each workspace whose tabs land, the hotkey window's too; only tabs restore found dead, never hibernated ones: `RestoredDead`, kept in `restored-asleep.json` until a wake lands or the user hibernates or closes the tab, since the tree marks every sleeping tab `hibernated`; `Wake`), which dead tabs restore asleep; the Startup & Restore rows (Resume agents on workspace restart, Agents starting at once, How agents resume, Continue interrupted agents, Continue message — the last an input built with the page's others: `build_continue_prompt_input`), the restart wake and the quit/restart dialog copy; `wake_tab_with` (a wake whose resumes carry a prompt, via the scoped `WakePrompt`); `Resume` (`Resume::restored`, what a restored agent pane reopens, its line quoted for the pane's shell; an interrupted turn gets `continue_prompt` under `continue_interrupted_agents`); `spawn_job` / `landed`, a pending pane's spawn and landing: under `agent_resume_mode: program` (local, replacing a known pane, sh/bash/zsh/dash/ksh/fish) the resume rides the spawn as `RestoreFrom::run_once`, else it is typed at the first prompt, the plan read off the UI thread either way; `with_minted_session`, Claude's `--session-id` minted at launch |
| `src/ui/wake_pool.rs` | the wake pool: Continue All Agents and the launch/restart wakes start at most `agent_wake_concurrency` tabs at once (default a quarter of the cores, 1–20), a slot freed when the tab's agent reports a session or after 60s; the queued/starting spinner (`state_mark`); the Agents starting at once slider; `put_to_sleep` and `asleep_tab` made `pub(crate)` for its tests |
| `src/ui/first_prompt.rs` | typing a quick launch's line, or a typed resume, at a new shell's first prompt: `type_at_first_prompt`, and `prompt_patience` (30s for a shell with integration, 3s without) (+ tests) |
| `crates/tty7-core/src/daemon/run_once.rs` | a command a new pane runs once: `TTY7_RUN_ONCE` for an integrated zsh/bash/fish, else `-lic '<cmd>; exec <shell>'`, never the recorded shell (+ tests) |
| `crates/tty7-server/tests/run_once.rs` | zsh, bash and sh run it once, with integration and the user's `ZDOTDIR` (fish untested: not installed here) |
| `crates/tty7-core/src/core/claude_background.rs` | Claude sessions running in the background: session ↔ job id from `sessions/<pid>.json`, or `jobs/<job>/state.json` when the job has no live process; `resume_plan` (resume an interrupted turn; attach, resume, or start fresh when nothing was saved); `adopt_argv_session`, the session id an agent's argv names, a miss (or an attach's job) re-read every 30s; `local_claude_root`; `ResumePlan::Closed`, a session whose transcript ends with the user's own `/exit` or `/quit`; `PaneRecord::last_session`: `note_session` sets it from every session an agent reports (only a new reported session replaces it, so a crash, a reboot or a sessionless `claude --version` keeps it) and drops it when `closed_on_leaving` finds the agent that just left was `/exit`ed (read by the daemon, on the transcript's host); `note_command` clears it when the shell starts a command (OSC 133 C) with no agent in front, unless that command is an agent's own; `with_last_session`, a record's agent with that session filled in per field; `interrupted`, read off the transcript's last 1MB (a cut-off turn, or one that ended waiting on a background launch, by its `tool_use`, nothing has since named) |
| `crates/tty7-core/src/core/fork_host.rs` | `ForkHost` (history search, session mentions) behind `Host::fork`: the local host's answers, and `NoFork`'s nothing-found for every other host |
